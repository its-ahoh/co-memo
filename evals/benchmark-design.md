# Agent 效果 Benchmark 设计稿（草案）

状态：草案，待确认。日期：2026-10-26。

## 1. 要回答的问题

现在的测试只证明"记忆存得对、取得对"。它们没有回答：

> 装了 Co-memo 之后，Agent 做真实编码任务，是不是真的做得更好？

这个 Benchmark 只回答这一个问题，并给出一个数字。

## 2. 核心方法：同一批任务，比较 3 组

| 组别         | 怎么做                                         | 作用       |
| ------------ | ---------------------------------------------- | ---------- |
| **无记忆**   | 不装 Co-memo                                   | 最低线     |
| **Co-memo**  | 正常安装 Co-memo，Agent 自己决定存什么、取什么 | 我们的成绩 |
| **满分参考** | 不装 Co-memo，把规则直接写进考试的提示词       | 理论上限   |

三组用同一个模型、同一份项目代码、同一套题目。唯一不同的就是"记忆从哪来"。

读结果的方法：

- **Co-memo − 无记忆** = 记忆带来的真实提升。
- **满分参考 − Co-memo** = 我们还漏掉的部分。差距越小越好。

## 3. 每道题的结构：先上课，再考试

1. **上课（第 1 次会话）**
   给 Agent 一个小任务。用户在对话里顺口交代一条规则。不说"请记住"。
   三组都要上这节课，这样才公平。
2. **（可选）干扰会话**
   做几个不相关的小任务，让真正的规则被埋在别的内容里。
3. **考试（第 2 次会话，全新会话）**
   给一个普通编码任务，**不提那条规则**。
   用程序检查 Agent 有没有自己遵守。

满分参考组跳过上课，直接把规则放进考试提示词。

## 4. 题目（第一版，10 题）

规则要特意选 **"和常见默认做法相反"** 的。否则 Agent 不靠记忆也会做对，测不出差别。

所有内容都是编的示例，不使用真实用户对话。

| #   | 类型       | 上课时交代的规则                               | 考试任务                   | 自动检查                                     |
| --- | ---------- | ---------------------------------------------- | -------------------------- | -------------------------------------------- |
| 1   | 项目决定   | 这个项目用 pnpm，不用 npm                      | 加一个依赖并写个小功能     | 没跑 `npm install`；没有 `package-lock.json` |
| 2   | 项目约定   | 新测试放 `spec/`，不放 `test/`                 | 给某函数补测试             | 新测试文件在 `spec/` 下                      |
| 3   | 项目约定   | 不用 `console.log`，用 `src/logger.js`         | 给某流程加日志             | diff 里没有 `console.log`，调用了 logger     |
| 4   | 项目约定   | 报错信息一律写中文                             | 加参数校验                 | 新的 `throw` 文案含中文                      |
| 5   | 禁区       | `src/legacy/` 不许改                           | 修一个牵涉 legacy 的 bug   | `src/legacy/` 没有改动，测试通过             |
| 6   | 规则被修正 | 先说"用 Jest"，后来说"改成 `node:test` 了"     | 写测试                     | 用的是 `node:test`，没有引入 Jest            |
| 7   | 个人偏好   | 我所有项目的 commit 都用英文 conventional 格式 | **在另一个项目里**提交改动 | commit 信息符合 `feat:`/`fix:` 格式且为英文  |
| 8   | 不该串项目 | 项目 B 用 tab 缩进                             | 在项目 A（用空格）里写代码 | 项目 A 的新代码仍是空格                      |
| 9   | 临时要求   | "这次先别写测试"（只限这次）                   | 加一个新功能               | 这次**有**写测试                             |
| 10  | 跨 Agent   | Claude 上课                                    | **Codex** 考试（第二阶段） | 同第 1 题的检查                              |

第 8、9 题是"防伤害"题：确认记忆不会把错误的东西带进来。
第 10 题是 Co-memo 独有的卖点，放到第二阶段再做。

## 5. 打分

每次运行记录：

- **规则遵守**（主指标）：自动检查通过 = 1，否则 = 0。
- **任务完成**：项目自带的测试是否通过。
- **成本**：token 数、花费、耗时、工具调用次数。

另外，Co-memo 组再记一个 **"漏斗"**，用来找出问题出在哪一步：

1. 上课后，**存了吗？**（看数据库）
2. 考试时，**取到了吗？**（看 `memory_context` 的返回内容）
3. 取到后，**照做了吗？**（看自动检查结果）

比如"存了也取到了，但没照做"，说明要改的是给 Agent 的提示方式，而不是检索。

## 6. 运行方式

- 新脚本：`scripts/bench-agent.mjs`；命令：`pnpm bench`。
  可选参数：`--reps 3`、`--jobs 3`、`--cases a,b`、`--arms none,comemo,oracle`、`--model`、`--budget 1`（每次会话的美元上限）、`--keep`（保留临时目录方便排查）。
- 所有题目、共用的小项目代码和检查函数都在 `evals/bench/cases.mjs`。
  `test/bench-cases.test.mjs` 为每道题各准备一个"守规则"和一个"违规"的结果，离线确认检查函数判得对，不花钱。
- 每次运行都用全新的临时目录和临时数据库。不碰真实记忆，也不读用户的 `CLAUDE.md`、hooks、插件、Claude 自带的 auto-memory（沿用 `eval-autonomous.mjs` 的隔离做法）。
- 上课会话只给只读工具（Read/Glob/Grep），改不了文件。所以"无记忆"和"满分参考"组上课不会影响考试，直接跳过，省钱。考试前还会把项目重置回初始状态。
- Co-memo 组使用默认的"仅工具"模式和关键词检索（`CO_MEMO_SEMANTIC=0`）。
- 每题每组跑 **3 次**（Agent 每次结果会不同）。
- 终端打印一张小表，完整 JSON 输出到 stdout，可重定向保存到 `evals/results/bench-<agent>-<日期>.json`：

```
题目            无记忆   Co-memo   满分参考
pnpm            0/3      3/3       3/3
spec 目录       0/3      2/3       3/3
...
总计            12%      78%       95%
```

- 要花钱，所以**只在发版前手动跑**，不放进 CI。
- 每次运行设花费上限（沿用 `--max-budget-usd`）。粗估第一版：10 题 × 3 组 × 3 次 ≈ 90 次 Agent 调用。

## 7. 公平性和防作弊

- 考试提示里绝不出现规则本身或暗示。
- 项目代码里不能有能"猜出"规则的线索（比如不放 `pnpm-lock.yaml`，否则 Agent 看文件就知道用 pnpm）。
- 先跑一遍"无记忆"组：如果某题无记忆也几乎全对，说明题太简单，要换掉。
- 检查只看客观结果（文件、diff、命令记录、commit），不让模型自己打分。

## 8. 分两步做

- **第一阶段**：只测 Claude，第 1–9 题，3 组。目标是拿到第一份真实数字。
- **第二阶段**：加 Codex 和第 10 题（跨 Agent），再按第一阶段暴露的问题加题。

## 9. 不做的事

- 不追求"通用记忆能力"的大型 Benchmark。只测我们关心的编码场景。
- 不用 LongMemEval / LoCoMo 这类聊天记忆测评，它们不测写代码。
- 不自动调参。数字只用来发现问题，改动仍然人工决定。

## 10. 需要你决定的

1. **考试前要不要加"干扰会话"？**
   - 加：更像真实使用，规则被埋得更深，但花费大约翻倍。
   - 不加（建议第一版先不加）：便宜、先看到数字，之后再加。
2. **上课时 Co-memo 组是否完全让 Agent 自己决定存不存？**
   - 是（建议）：测的是真实使用效果。
   - 另加一组"预先写好记忆"：能把"存的问题"和"取的问题"分开看，但多一组花费。漏斗指标已经能部分区分，所以建议先不加。
